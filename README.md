# Columbia / KRYGA — лендинги и общая админка (React + Vite)

Админка — `/admin`. Здесь выбирается сайт, который открывается по основному адресу
для всех посетителей. По умолчанию активен KRYGA; инструкция общей панели ниже.

Украинский по адресу `/`, русский по адресу `/ru`. Страница «Дякуємо» — `/thanks` и `/ru/thanks`, политика — `/privacy`.
Заявки уходят на `/api/lead` → DarkLeads (оффер 120151, поток 98053, CPA 1317, 1199 грн).

## Разработка

```bash
npm install
npm run dev
```

В dev-режиме `/api/lead` отвечает **заглушка** (`vite.config.js`), реальные лиды не уходят. Meta Pixel в dev выключен (`.env.development`).

## Деплой на Vercel

1. Импортируйте папку в Vercel (Framework: Vite — подхватится из `vercel.json`).
2. Settings → Environment Variables: `DARKLEADS_API_KEY` = ключ DarkLeads.
3. Deploy. Заявки обрабатывает `api/lead.js`, лог заявок — в Vercel → Logs.

## Деплой на обычный хостинг (Apache + PHP)

```bash
npm run build:php
```

Загрузите **содержимое** `dist/` в корень сайта. Там уже лежат `api.php`, `config.php` (ключ) и `.htaccess`
(перенаправляет `/api/lead` → `api.php`, открывает `/ru`, `/thanks`, закрывает `config.php` и `orders.log`).
Ключ меняется в `server/php/config.php` (файл не попадает в git).

## Что заполнить перед запуском

- `src/i18n.js` — данные продавца (ФОП) и контакт: строки с пометкой «ЗАПОВНИТИ / ЗАПОЛНИТЬ».
- `src/config.js` — цвета в наличии (по офферу подтверждён только чёрный) и размерная сетка (ориентировочная).
- Страна производства «Німеччина» взята из данных поставщика — сверить с биркой.
- Фото — сток (Unsplash) и Wikimedia Commons с указанием авторов в футере. Заменить на свою съёмку, когда будет.

## Пиксель

`VITE_FB_PIXEL_ID` в `.env`. PageView — на каждой странице, **Lead — один раз на странице «Дякуємо»** после успешной заявки
(повторная загрузка или прямой заход на `/thanks` Lead не шлёт).

## Общая панель Columbia / KRYGA

Из корня проекта `npm run dev`, затем откройте `http://localhost:5173/admin`.
Выберите сайт и нажмите «Применить переключение». Основной адрес `/`, языки `/ru`
и служебные страницы открывают выбранный лендинг. Изменение действует для всех
браузеров при следующем открытии/обновлении страницы. Открытые формы не прерываются.
«Предпросмотр» (`/?preview=columbia` или `/?preview=kryga`) не меняет общий выбор;
пиксель в предпросмотре и админке не запускается. Формы предпросмотра подключены
к обработчику соответствующего сайта, как и обычные формы; в dev это заглушки.

В разработке и `npm run preview` выбор сохраняется в `.local/site-state.json`.
Для входа задайте `SITE_ADMIN_USERNAME` (по умолчанию `admin`) и
`SITE_ADMIN_PASSWORD` в игнорируемом `.env.local`, затем перезапустите Vite.
Без пароля вход закрыт. Локальные сессии сбрасываются при перезапуске сервера. Dev-сервер предназначен
для loopback, его нельзя использовать как публичный production-сервер.

### Apache + PHP

1. Скопируйте `server/php/site-admin.config.example.php` в
   `server/php/site-admin.config.php`. Заполните `password_hash` результатом
   `password_hash(ваш_пароль, PASSWORD_DEFAULT)` в PHP. Пароль не хранится в браузере.
2. Укажите `state_file` — абсолютный путь вне публичной папки сайта, доступный PHP
   для записи. Этот файл сохраняется между обновлениями сборки; не перезаписывайте
   его при загрузке `dist/`. Без настроенного пароля смена сайта запрещена.
3. Настройте отдельный `columbia-site/server/php/config.php` по его примеру:
   ключ, товар и поток Columbia. Без них форма Columbia вернёт ошибку конфигурации.
4. `npm run build:php`, затем загрузите содержимое `dist/` на Apache с mod_rewrite.
   Используйте HTTPS. `/api/site` обслуживается `site.php`, `/api/admin` — `admin.php`.
   Вход использует PHP-сессии; каталог с `state_file` также хранит счётчик попыток входа.

KRYGA отправляет заявки на `/api/lead`; Columbia — на `/api/columbia-lead`.
Настройки Columbia не наследуют оффер и ключи KRYGA. `.htaccess` закрывает конфиги
и логи от прямого просмотра и передаёт заголовок авторизации PHP.

### Vercel

В дополнение к существующим переменным добавьте серверные (без префикса `VITE_`):

- `SITE_ADMIN_USERNAME` — логин администратора, по умолчанию `admin`;
- `SITE_ADMIN_PASSWORD` — пароль для входа в панель;
- `KV_REST_API_URL` и `KV_REST_API_TOKEN` — постоянное общее хранилище; эти переменные
  добавляет интеграция Upstash через Vercel Marketplace. Для прямого подключения
  также поддерживаются `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`;
- `SITE_STATE_KEY` — необязательно, по умолчанию `storefront:active-site`;
- `COLUMBIA_DARKLEADS_API_KEY`, `COLUMBIA_DARKLEADS_PRODUCT_ID`,
  `COLUMBIA_DARKLEADS_STREAM_ID`, при необходимости `COLUMBIA_DARKLEADS_CPA_ID`,
  `COLUMBIA_DARKLEADS_PRICE`, `COLUMBIA_DARKLEADS_ENDPOINT` — только для Columbia;
- `VITE_COLUMBIA_FB_PIXEL_ID` — отдельный пиксель Columbia, необязательно.

Без Redis используется KRYGA по умолчанию. Без Redis или пароля вход в панель закрыт. Файловая система serverless для сохранения не используется.
Протокол хранилища: [официальный Redis REST API](https://upstash.com/docs/redis/features/restapi).
Все ответы `/api/site` имеют `Cache-Control: no-store`; не включайте CDN-кеш для API.

Это клиентская SPA: HTML-метаданные до запуска JavaScript общие, а название,
описание и canonical обновляются выбранным приложением. Для отдельных SEO-превью
соцсетей до выполнения JS потребуется серверный рендеринг.

### Вход в админку

На `/admin` сначала отображается форма логина и пароля. Данные проверяет сервер
`/api/admin`; панель загружается после успешного входа. Сессия хранится в Redis
8 часов, браузер получает cookie `HttpOnly`, `Secure`, `SameSite=Strict`.
«Выйти» удаляет сессию на сервере; изменение логина или пароля также отменяет
старые сессии после нового деплоя. Пароль не сохраняется в коде или localStorage.
Допускается 10 попыток входа с одного IP за 15 минут. Локальная разработка
использует память процесса вместо Redis и cookie без Secure для loopback HTTP.

Публичный GET `/api/site` нужен посетителям для выбора витрины. POST `/api/site`
требует действующую сессию; прежний Bearer-пароль больше не принимается.
Изменяющие запросы проверяют Origin и требуют JSON; CORS не включать.

`node --test tests/*.test.mjs` — сохранение между обработчиками, авторизация,
валидация, отсутствие хранилища и отказ при повреждённом состоянии.
